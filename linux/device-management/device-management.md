# 장치의 설치 및 관리

## 1. 모듈

### 모듈 개요

모듈(Module)은 커널의 기능을 필요할 때 동적으로 추가하거나 제거할 수 있도록 만든 코드이다.

하드웨어 장치를 지원하거나 파일 시스템, 네트워크 기능 등을 커널에 추가할 때 사용한다.

- 필요한 기능을 동적으로 추가하거나 제거할 수 있음
- 커널 전체를 다시 컴파일하지 않고 기능을 추가할 수 있음
- 일반적으로 커널 모듈 파일은 `.ko` 확장자를 사용

### 모놀리식 커널

커널에 필요한 기능을 모두 포함하여 하나의 커널 이미지로 구성하는 방식이다.

- 대부분의 기능이 커널에 포함됨
- 기능 추가나 변경 시 커널을 다시 컴파일해야 할 수 있음
- 커널의 크기가 커질 수 있음

### 모듈 방식

필요한 기능을 모듈 형태로 분리하여 필요할 때 커널에 적재하는 방식이다.

- 필요한 기능만 동적으로 적재할 수 있음
- 필요하지 않은 모듈은 제거할 수 있음
- 커널을 다시 컴파일하지 않고 기능을 추가할 수 있음
- 필요한 기능을 선택적으로 사용할 수 있음

### 모듈 관련 설정 파일

- `/etc/modprobe.d/` → 모듈 관련 설정 파일을 저장하는 디렉터리
- `/etc/modprobe.conf` → 모듈 설정 파일

### 모듈 의존성

하나의 모듈이 다른 모듈을 필요로 하는 경우 모듈 의존성이 발생한다.

모듈을 적재할 때 필요한 다른 모듈도 함께 고려해야 한다.

### modules.dep

모듈 간의 의존 관계를 기록한 파일이다.

일반적으로 `/lib/modules/커널버전/modules.dep` 경로에 존재한다.

`depmod` 명령을 통해 모듈 의존성 정보를 생성하거나 갱신할 수 있다.

## 2. 커널

### 커널 개요

커널(Kernel)은 운영체제의 핵심 부분으로, 하드웨어와 응용 프로그램 사이에서 시스템 자원과 하드웨어를 관리한다.

주요 역할:

- CPU 관리
- 메모리 관리
- 프로세스 관리
- 파일 시스템 관리
- 장치 관리
- 네트워크 관리

응용 프로그램은 시스템 호출(System Call)을 통해 커널의 기능을 사용할 수 있다.

### 커널 컴파일

커널 컴파일은 커널 소스 코드를 이용하여 시스템에서 사용할 커널을 생성하는 과정이다.

일반적인 과정:

커널 소스 코드 준비 → 커널 설정 → 커널 및 모듈 컴파일 → 커널 모듈 설치 → 커널 설치 → 부트로더 설정 → 재부팅

### 커널 컴파일 과정

#### 1. 커널 소스 코드 준비

커널 소스 코드를 준비하고 압축을 해제한다.

#### 2. 커널 설정

시스템에 필요한 기능을 선택하고 커널 설정을 구성한다.

대표적인 설정 도구:

- `make config`
- `make menuconfig`
- `make nconfig`
- `make xconfig`
- `make gconfig`

#### 3. 커널 및 모듈 컴파일

설정된 내용을 기반으로 커널과 커널 모듈을 컴파일한다.

#### 4. 커널 모듈 설치

컴파일된 커널 모듈을 시스템에 설치한다.

#### 5. 커널 설치

생성된 커널과 관련 파일을 시스템에 설치한다.

#### 6. 부트로더 설정

부트로더에서 새로 설치된 커널을 선택하여 부팅할 수 있도록 설정한다.

#### 7. 재부팅

새롭게 설치된 커널로 시스템을 부팅한다.

## 3. Cleaning Targets

커널 소스를 컴파일한 후 생성된 파일을 정리할 때 `make`의 Cleaning Target을 사용할 수 있다.

### make clean

커널 컴파일 과정에서 생성된 대부분의 생성 파일을 삭제한다.

- 설정 파일은 유지
- 빌드 결과물을 정리할 때 사용

### make mrproper

`make clean`보다 더 많은 파일을 정리한다.

- 컴파일 결과물 삭제
- `.config` 등의 설정 파일 삭제
- 커널 소스를 깨끗한 상태로 초기화할 때 사용

### make distclean

`make mrproper`보다 더 광범위하게 정리한다.

- 컴파일 결과물 삭제
- 설정 파일 삭제
- 추가적인 생성 파일 및 백업 파일까지 제거

### Cleaning Targets 비교

- `make clean` → 컴파일 결과물 정리
- `make mrproper` → `clean` + 설정 파일 등 추가 정리
- `make distclean` → `mrproper` + 추가 생성/백업 파일까지 정리

## 4. 커널 컴파일 주요 도구

커널을 컴파일하기 전에 시스템에 필요한 기능을 선택하고 설정할 수 있다.

### make config

터미널에서 질문에 답하는 방식으로 커널 설정을 진행한다.

- 가장 기본적인 커널 설정 방식
- 각 항목에 대해 순차적으로 설정

### make menuconfig

터미널 기반의 메뉴 방식으로 커널 설정을 진행한다.

- 메뉴 기반 설정
- 키보드를 이용하여 설정

### make nconfig

`menuconfig`와 유사한 터미널 기반의 커널 설정 도구이다.

- 메뉴 기반 설정
- `menuconfig`보다 개선된 인터페이스 제공

### make xconfig

X Window 환경에서 GUI를 이용하여 커널을 설정한다.

- Qt 기반 인터페이스
- 그래픽 환경 필요

### make gconfig

X Window 환경에서 GUI를 이용하여 커널을 설정한다.

- GTK 기반 인터페이스
- 그래픽 환경 필요

### 커널 설정 도구 비교

| 명령어 | 방식 | 특징 |
|---|---|---|
| `make config` | 텍스트 | 질문에 순차적으로 답하며 설정 |
| `make menuconfig` | 텍스트 메뉴 | 메뉴 기반 설정 |
| `make nconfig` | 텍스트 메뉴 | 개선된 메뉴 기반 설정 |
| `make xconfig` | GUI | Qt 기반 |
| `make gconfig` | GUI | GTK 기반 |

## 시험 포인트

- 모듈 → 커널 기능을 동적으로 추가하거나 제거할 수 있는 코드
- 커널 모듈 → `.ko`
- 모놀리식 커널 → 기능을 커널에 포함
- 모듈 방식 → 필요한 기능을 동적으로 적재
- `modules.dep` → 모듈 의존성 정보
- `make clean` → 컴파일 결과물 정리
- `make mrproper` → `clean`보다 더 많은 파일 정리, `.config` 제거
- `make distclean` → `mrproper`보다 더 광범위하게 정리
- `make config` → 텍스트 기반 순차 설정
- `make menuconfig` → 텍스트 메뉴 기반 설정
- `make nconfig` → 개선된 텍스트 메뉴 기반 설정
- `make xconfig` → Qt 기반 GUI
- `make gconfig` → GTK 기반 GUI
