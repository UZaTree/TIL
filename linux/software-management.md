# 소프트웨어 설치 및 관리

## RPM 패키지

RPM(Red Hat Package Manager)은 RPM 패키지를 설치하고 관리하는 패키지 관리 도구이다.

### 패키지

패키지는 프로그램과 프로그램 실행에 필요한 파일, 설정 정보, 의존성 정보 등을 하나로 묶어 관리하는 배포 단위이다.

RPM에서는 `.rpm` 파일 하나가 패키지에 해당한다.

패키지는 프로그램 그 자체가 아니라 **프로그램과 설치 및 관리에 필요한 정보를 묶어 놓은 배포 단위**이다.

## RPM 패키지 파일명

RPM 패키지 파일은 일반적으로 다음과 같은 형식으로 구성된다.

`패키지이름-버전-릴리즈.리눅스버전.아키텍처.rpm`

예:

`httpd-2.4.57-8.el9.x86_64.rpm`

| 구성 요소 | 설명 | 예시 |
|---|---|---|
| 패키지이름 | 설치할 패키지의 이름 | `httpd` |
| 버전(Version) | 패키지 자체의 버전 | `2.4.57` |
| 릴리즈(Release) | 동일 버전에서 패키지가 몇 번째로 배포되었는지 나타냄 | `8` |
| 리눅스 버전 | 해당 패키지가 만들어진 배포판 또는 배포판 계열을 나타냄 | `fc38`, `el8`, `el9`, `centos` |
| 아키텍처(Architecture) | 패키지가 실행될 CPU 아키텍처를 나타냄 | `x86_64` |
| `.rpm` | RPM 패키지 파일임을 나타내는 확장자 | `.rpm` |

### 리눅스 버전 표기 예시

| 표기 | 의미 |
|---|---|
| `fc38` | Fedora 38 |
| `el8` | Enterprise Linux 8 계열 |
| `el9` | Enterprise Linux 9 계열 |
| `centos` | CentOS 계열 |

### 아키텍처 표기 예시

| 표기 | 설명 |
|---|---|
| `i386` | Intel 80386 계열 32비트 |
| `i486` | Intel 80486 계열 32비트 |
| `i586` | Intel Pentium 계열 32비트 |
| `i686` | Intel Pentium Pro 이상 계열 32비트 |
| `ia64` | Intel Itanium 64비트 |
| `x86_64` | x86 기반 64비트 |
| `alpha` | DEC Alpha 계열 |
| `ppc` | PowerPC 계열 |
| `ppc64` | PowerPC 64비트 |
| `sparc` | SPARC 계열 |
| `s390` | IBM System/390 계열 |
| `aarch64` | ARM 64비트 |

> **시험 포인트**
>
> - `i386`, `i486`, `i586`, `i686` → x86 **32비트 계열**
> - `x86_64` → x86 **64비트**
> - `ia64` → **Itanium** 계열
> - `alpha` → **Alpha** 계열
> - `ppc`, `ppc64` → **PowerPC** 계열
> - `aarch64` → **ARM 64비트**

## RPM 사용법

기본 사용법:

`rpm [option] [패키지_파일명]`

RPM의 주요 기능은 다음 5가지 모드로 구분한다.

| 모드 | 설명 |
|---|---|
| 설치 및 갱신 | 패키지를 설치하거나 기존 패키지를 갱신 |
| 제거 | 설치된 패키지를 삭제 |
| 질의 | 패키지의 정보 및 설치 상태 등을 확인 |
| 검증 | 설치된 패키지의 파일 상태를 검증 |
| 리빌드 | 소스 RPM(`.src.rpm`)을 바이너리 RPM으로 재빌드 |

## 설치 및 갱신 모드

| 옵션 | 설명 |
|---|---|
| `-i` | 패키지 설치 |
| `-U` | 패키지 갱신. 기존 패키지가 없으면 설치 |
| `-F` | 패키지 갱신. 기존 패키지가 설치되어 있는 경우에만 갱신 |
| `-v` | 자세한 정보 출력 |
| `-h` | 설치 진행 상황을 `#`으로 표시 |
| `--force` | 기존 파일이나 패키지가 있어도 강제로 설치 |
| `--nodeps` | 의존성 검사를 하지 않음 |
| `--vv` | 매우 자세한 디버깅 정보 출력 |
| `--test` | 실제 설치하지 않고 설치 가능 여부만 테스트 |
| `--rebuilddb` | RPM 데이터베이스 재구축 |

## 제거 모드

| 옵션 | 설명 |
|---|---|
| `-e`, `--erase` | 패키지 제거 |
| `--nodeps` | 의존성 검사를 하지 않음 |
| `--test` | 실제 제거하지 않고 제거 가능 여부만 테스트 |
| `--allmatches` | 이름이 일치하는 모든 패키지 제거 |

## 질의 모드

질의 모드는 설치된 패키지 또는 RPM 패키지 파일에 대한 정보를 확인한다.

### 주요 옵션

| 옵션 | 설명 |
|---|---|
| `-q` | 질의(Query) 모드 |
| `-i` | 패키지 정보(Information) 출력 |
| `-l` | 패키지가 설치한 파일 목록(List) 출력 |
| `-a` | 설치된 모든 패키지 출력 |
| `-p 패키지_파일명` | RPM 패키지 파일을 대상으로 질의 |
| `-f 파일명` | 해당 파일을 설치한 패키지 확인 |
| `-c` | 패키지의 설정 파일 목록 출력 |
| `-d` | 패키지의 문서 파일 목록 출력 |
| `-R` | 패키지의 의존성 정보 출력 |
| `--changelog` | 패키지 변경 이력 출력 |
| `--scripts` | 패키지에 포함된 스크립트 출력 |
| `--filesbypkg` | 패키지별 설치 파일 목록 출력 |
| `--queryformat` | 질의 결과의 출력 형식 지정 |

### `-i`와 `-l`의 차이

| 옵션 | 의미 | 결과 |
|---|---|---|
| `-i` | Information | 패키지의 상세 정보 |
| `-l` | List | 패키지가 설치하는 파일 목록 |

예:

`rpm -qi httpd`

→ 설치된 `httpd` 패키지의 상세 정보를 출력한다.

`rpm -ql httpd`

→ `httpd` 패키지가 설치한 파일 목록을 출력한다.

### 패키지 파일을 대상으로 질의

`-p`는 설치된 패키지가 아니라 **RPM 패키지 파일을 대상으로 질의**한다.

`-qpi package.rpm`

→ 설치하지 않은 RPM 패키지 파일의 상세 정보를 출력한다.

`-qpl package.rpm`

→ RPM 패키지 파일에 포함된 파일 목록을 출력한다.

> **시험 포인트**
>
> - `-q` → Query(질의)
> - `-p` → 패키지 파일을 대상으로 질의
> - `-i` → Information(상세 정보)
> - `-l` → List(파일 목록)
>
> 따라서 `rpm -qpi package.rpm`은 **설치하지 않고 RPM 패키지 파일의 상세 정보를 확인**하는 명령이다.

## 검증 모드

검증 모드는 설치된 패키지의 파일이 설치 당시와 동일한 상태인지 확인한다.

`rpm -V [패키지명]`

### 검증 코드

| 코드 | 의미 |
|---|---|
| `S` | 파일 크기(Size) 변경 |
| `M` | 파일 권한 및 모드(Mode) 변경 |
| `5` | MD5 체크섬 변경 |
| `D` | 장치(Device) 정보 변경 |
| `L` | 심볼릭 링크(Link) 변경 |
| `U` | 사용자 소유자(User) 변경 |
| `G` | 그룹 소유자(Group) 변경 |
| `T` | 수정 시간(Time) 변경 |
| `P` | 권한 관련 속성 변경 |
| `.` | 변경 없음 |
| `?` | 검증할 수 없음 |

### 검증 옵션

| 옵션 | 설명 |
|---|---|
| `-V` | 검증(Verify) |
| `-a` | 설치된 모든 패키지 검증 |

## rpmbuild

`rpmbuild`는 RPM 패키지를 빌드하는 도구이다.

`rpm`이 이미 만들어진 RPM 패키지를 설치, 제거, 질의, 검증하는 도구라면 `rpmbuild`는 RPM 패키지를 생성하거나 재빌드하는 데 사용한다.

### RPM과 rpmbuild

`소스 코드 → SPEC 파일 → rpmbuild → 바이너리 RPM(.rpm) → rpm으로 설치`

### 소스 RPM

소스 RPM은 `.src.rpm` 확장자를 사용하는 소스 패키지이다.

소스 코드와 SPEC 파일 등 RPM 패키지를 빌드하는 데 필요한 파일을 포함한다.

일반적인 `.rpm` 파일은 실제 시스템에 설치하는 바이너리 패키지이다.

### `--rebuild`

소스 RPM을 다시 빌드하여 바이너리 RPM을 생성한다.

`rpmbuild --rebuild package.src.rpm`

처리 과정:

`package.src.rpm → rpmbuild --rebuild → package.rpm`

| 옵션 | 설명 |
|---|---|
| `--rebuild` | 소스 RPM을 재빌드하여 바이너리 RPM 생성 |
| `-ba` | 소스 RPM과 바이너리 RPM 모두 빌드 |
| `-bb` | 바이너리 RPM만 빌드 |
| `-bs` | 소스 RPM만 빌드 |

> **시험 포인트**
>
> - `rpm` → RPM 패키지 **관리**
> - `rpmbuild` → RPM 패키지 **빌드**
> - `rpmbuild --rebuild` → **소스 RPM(`.src.rpm`)을 다시 빌드하여 바이너리 RPM 생성**
