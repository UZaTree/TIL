## 라이브러리

### 라이브러리 파일 명칭

리눅스에서 라이브러리 파일은 크게 정적 라이브러리와 공유 라이브러리로 구분한다.

- 정적 라이브러리 → `lib이름.a`
- 공유 라이브러리 → `lib이름.so`
- 공유 라이브러리의 버전이 있는 경우 → `lib이름.so.버전`

예:
- `libc.a` → 정적 라이브러리
- `libc.so` → 공유 라이브러리

### 라이브러리의 개요

라이브러리(Library)는 프로그램에서 자주 사용하는 기능을 미리 구현해 놓은 코드의 모음이다.

프로그램에서 필요한 기능을 라이브러리에서 가져와 사용할 수 있기 때문에 동일한 기능을 매번 직접 구현할 필요가 없다.

라이브러리에 포함될 수 있는 대표적인 요소:

- 서브루틴(Subroutine) → 특정 작업을 수행하도록 만들어진 코드
- 함수(Function) → 특정 기능을 수행하는 코드 단위
- 클래스(Class) → 객체와 관련된 데이터와 기능을 묶어 놓은 코드 단위

프로그램이 라이브러리의 기능을 사용하기 위해서는 링크(Link) 과정이 필요하다.

### 정적 라이브러리

정적 라이브러리는 프로그램을 컴파일하고 링크할 때 필요한 라이브러리 코드를 실행 파일에 포함시키는 방식이다.

- 파일 확장자 → `.a`
- 필요한 라이브러리 코드가 실행 파일에 포함됨
- 실행 시 별도의 공유 라이브러리에 의존하지 않을 수 있음
- 실행 파일의 크기가 커질 수 있음

### 공유 라이브러리

공유 라이브러리(Shared Library)는 여러 프로그램이 하나의 라이브러리를 공유하여 사용하는 방식이다.

- 파일 확장자 → `.so`
- 실행 파일에 라이브러리 코드 전체를 직접 포함하지 않고 필요한 공유 라이브러리를 이용
- 여러 프로그램이 동일한 라이브러리를 공유할 수 있음
- 메모리와 디스크 공간을 절약할 수 있음
- 실행 시 필요한 공유 라이브러리에 대한 의존성(Dependency)이 발생함

### 공유 라이브러리의 특징

#### 의존성

공유 라이브러리를 사용하는 프로그램은 실행할 때 해당 공유 라이브러리가 필요하다.

필요한 공유 라이브러리가 없거나 적절한 버전을 찾지 못하면 프로그램이 정상적으로 실행되지 않을 수 있다.

#### 링크

공유 라이브러리는 프로그램과 라이브러리를 연결하는 링크 과정과 관련된다.

공유 라이브러리를 사용하는 프로그램은 실행 시 필요한 라이브러리를 찾아 사용할 수 있다.

### 공유 라이브러리 관련 디렉터리

- `/lib` → 기본 시스템 공유 라이브러리
- `/lib64` → 64비트 시스템의 공유 라이브러리
- `/usr/lib` → 일반적인 공유 라이브러리
- `/usr/lib64` → 64비트 시스템의 공유 라이브러리
- `/usr/local/lib` → 관리자가 직접 설치한 라이브러리 등을 저장하는 데 사용

### 공유 라이브러리 관련 파일

- `/etc/ld.so.conf` → 공유 라이브러리를 검색할 디렉터리 설정 파일
- `/etc/ld.so.cache` → 공유 라이브러리의 위치를 빠르게 찾기 위한 캐시 파일

### 공유 라이브러리 관련 명령어

#### ldconfig

공유 라이브러리의 캐시를 생성하거나 갱신하는 명령어.

주요 옵션:

- `-p` → 현재 캐시에 등록된 공유 라이브러리 목록 출력
- `-v` → 처리 과정 및 라이브러리 정보를 자세히 출력
- `-f` → 설정 파일 지정

#### ldd

실행 파일이나 프로그램이 필요로 하는 공유 라이브러리의 의존 관계를 확인하는 명령어.

주요 옵션:

- `-v` → 의존 관계를 자세히 출력
- `-f` → 지정한 형식으로 출력

### 시험 포인트

- 정적 라이브러리 → `.a`
- 공유 라이브러리 → `.so`
- 공유 라이브러리 → 여러 프로그램이 공유하여 사용
- 공유 라이브러리 → 실행 시 필요한 라이브러리에 대한 의존성이 있음
- `/etc/ld.so.conf` → 공유 라이브러리 검색 경로 설정
- `/etc/ld.so.cache` → 공유 라이브러리 캐시
- `ldconfig` → 공유 라이브러리 캐시 생성/갱신
- `ldd` → 공유 라이브러리 의존 관계 확인
