# 데이터 타입 (Data Types)

> column 생성 시 데이터의 종류를 명시해야 함

---

## 문자형

| 타입 | 저장 가능한 양 | 특징 |
|------|-------------|------|
| CHAR | 0 ~ 255자 | CHAR(숫자)로 최대 용량 지정, 고정 크기 |
| VARCHAR | 0 ~ 65535자 | VARCHAR(숫자)로 최대 용량 지정, 가변 크기 |
| TEXT | 0 ~ 65535자 | |
| TINYTEXT | 0 ~ 255자 | |
| MEDIUMTEXT | 0 ~ 1600만자 | 블로그 글 등 긴 글 저장 시 사용 |
| LONGTEXT | 0 ~ 42억자 | |

**일반적으로 VARCHAR 사용**

### CHAR vs VARCHAR
- `VARCHAR(300)` 으로 설정 후 10자 저장 → 실제 10자 + 1byte만 차지 (가변)
- `CHAR(10)` 으로 설정 후 5자 저장 → 무조건 10자만큼 차지 (고정)
- 항상 고정된 크기가 필요한 경우 CHAR가 성능상 이점, 하지만 드문 케이스

## 숫자형

| 타입 | 저장 가능한 양 | 특징 |
|------|-------------|------|
| SMALLINT | -32768 ~ 32767 | 2byte |
| MEDIUMINT | -838만 ~ 838만 | |
| INT | -21억 ~ 21억 | 4byte |
| BIGINT | -900경 ~ 900경 | 8byte |
| FLOAT | -10^38 ~ 10^38 | 소수점 7자리, 오차 있음 |
| DOUBLE | -10^308 ~ 10^308 | 소수점 14자리, 오차 있음 |
| DECIMAL | 소수점 30자리 포함 최대 65자리 | 오차 없이 소수점 저장 |

> Java의 int(-21억 ~ 21억), long(-922경 ~ 922경)과 비슷한 개념

### 참고
- 양의 숫자만 저장 시 `UNSIGNED` 옵션 → SMALLINT 기준 0 ~ 65535
- 숫자가 커진다고 DB 용량을 더 차지하는 게 아님, 타입에 따라 고정 byte
- 소수점이 필요하면 FLOAT/DOUBLE 보다 **정확도가 중요하면 DECIMAL** 사용

## 날짜/시간형

| 타입 | 저장 가능한 양 | 형식 |
|------|-------------|------|
| DATE | 1000년 ~ 9999년 | YYYY-MM-DD |
| TIME | -839 ~ +838시간 | HH:MM:SS |
| DATETIME | 1000년 ~ 9999년 | YYYY-MM-DD HH:MM:SS |
| TIMESTAMP | 1970년 ~ 2038년 | YYYY-MM-DD HH:MM:SS |

**일반적으로 DATETIME 사용**

> TIMESTAMP는 2038년까지만 저장 가능해서 잘 안 씀, 현재 DB 시간 기록 시 간혹 사용
